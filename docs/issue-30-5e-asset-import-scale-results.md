# Issue 30-5E Asset Import Scale Results

## Dataset

Default scale target:

- Existing assets: 100,000
- Upload rows: 10,000
- New unique rows: 2,000
- Exact matching rows: 2,000
- Valid update rows: 2,000
- Identity conflict rows: 1,000
- Duplicate pairs: 500 pairs, 1,000 rows total
- Invalid rows: 1,000
- Slot conflict rows: 1,000

Expected preview category totals:

- New Asset: 2,500
- Unchanged Exact Match: 2,000
- Proposed Update: 2,000
- Unslotted Import: 0
- Slot Conflict Eligible For Unslotted Import: 1,000
- Identity Conflict: 1,000
- Invalid Or Duplicate Upload Row: 1,500

The dataset is deterministic and generated by `tools/asset_import_scale_check.py`.

## Measurements

Initial full-dataset preview behavior before optimization:

- Dataset: 100,000 existing assets, 10,000 upload rows
- Result: direct preview did not complete after about 90 seconds
- Evidence: interrupted stack was in `_asset_by_tag()` during preview reconciliation
- Cause: repeated per-row case-insensitive lookups against large tables

After the preview lookup optimization:

- Dataset: 100,000 existing assets, 10,000 upload rows
- Seed: 0.746 seconds
- Analysis: 0.275 seconds
- Direct preview: 1.066 seconds
- Category totals: matched expected totals

Medium route measurement:

- Dataset: 10,000 existing assets, 1,000 upload rows
- Analysis: 0.021 seconds
- Direct preview: 0.086 seconds
- Upload route preview: 7.148 seconds
- Commit: 14.541 seconds
- Max RSS: 80.52 MB before route workflow, 125.31 MB after route workflow

## Integrity

Medium route integrity results:

- Expected and actual table counts matched
- Asset home-slot to slot-occupancy mismatches: 0
- Slot-occupancy to asset home-slot mismatches: 0
- Slot current-tag mismatches: 0
- Blocked rows inserted: 0
- Busy slots changed: 0

Rollback probe:

- Verified: true
- Probe assets inserted after forced mid-transaction failure: 0
- Counts before and after rollback: unchanged

## Full Route Result

Full route workflow did not complete at the 100,000 existing asset / 10,000 upload row target.

Observed thresholds:

- Upload route preview was still running after more than 120 seconds.
- Direct analysis and preview had already completed successfully before the route stall.
- Isolated normal database bootstrap/request setup against the seeded 100,000-row database exceeded 60 seconds.

The remaining proven bottleneck is normal database bootstrap/request handling, not import analysis parsing or direct preview reconciliation.

## Conclusion

The import analysis and direct preview path are now measurable and fast at 100,000 existing assets with a 10,000-row upload. The full browser route workflow is not yet operationally acceptable at 100,000 / 10,000 because normal request handling still stalls before completing upload-route preview.

Smallest safe follow-on issue:

Investigate normal database bootstrap and request handling performance for large local SQLite datasets used by the asset import route.

The follow-on should begin as Class 2 investigation. It must stop for Class 3 or Class 5 approval if acceptable performance requires an index, migration, schema change, persistence-semantics change, or infrastructure/runtime change.
